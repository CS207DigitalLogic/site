    Digital Logic: Environment Setup and Engineering Practice

    Objectives

    • Become familiar with the laboratory platform used in this course: the EDA tool and FPGA development board.
    • Understand the key requirements for installing and configuring Vivado.
    • Become familiar with the hardware components and basic architecture of the EGO1 development board.
    • Master the complete Vivado project development flow: creating a project, adding files, functional simulation, synthesis and implementation, bitstream generation, and on-board verification.
    • Understand the basic principles of FPGAs and how they differ from conventional CPUs.

    1. Experimental Platform

    This course uses a combination of an EDA tool and an FPGA development board for hardware experiments.

    1.1 EDA Tool: Vivado 2018.3

    • Purpose: Vivado is the development environment designed by Xilinx for its FPGA products. It enables developers to synthesize (compile) hardware designs, perform timing analysis, inspect RTL schematics, simulate circuit responses to different stimuli, and configure target devices through a programmer.
    • Version: This course standardizes on Vivado 2018.3.

    1.2 FPGA Development Board: EGO1

    • Main device: A Xilinx Artix-7 FPGA, part number xc7a35tcsg324-1.

    • Main on-board peripherals:

    • Power switch

    • Potentiometer
    • Five push buttons
    • Sixteen slide switches
    • Reset button
    • Eight seven-segment displays
    • Sixteen LEDs
    • Other interfaces: VGA, audio, USB-UART/JTAG (for connecting the board to a computer and programming it), and USB-PS/2

    2. Installing Vivado

    2.1 Important Notes

    Vivado requires substantial disk space and imposes strict requirements on paths. Observe the following points:

    • Disk space: Reserve at least 20 GB of free space on the target drive.
    • Path naming: The operating-system username, the folder containing the installation package, and the final Vivado installation path must not contain Chinese characters or spaces.
    • Download link: Refer to 'resources' on top of the website.
    • Installer and license: Download the installer archive Xilinx_Vivado_SDK_2018.3_1207_2324.tar.gz and the license archive Vivado2018.3_licence.zip, then extract both archives.
    • Edition: Select Vivado HL Design Edition in the installer.
    • Custom installation (to save space): On the component-selection screen, it is strongly recommended that you select only the components required for this course:
    • Expand 7 Series devices and select only Artix-7. Clear the selections for other devices such as Kintex-7 and Spartan-7.
    • Import the license: After installation, open Vivado License Manager, select Load License -> Copy License..., and import the downloaded .lic file.

    2.2 Installation Procedure

    • Extract the installer package and double-click xsetup.exe:

    • Skip the software update and click Continue:

    • On this screen, select I Agree:

    • Select the second option, Vivado HL Design Edition:

    • To save disk space, select only the component required for this course, Artix-7:

    • You may change the installation directory. Ensure that its path contains no Chinese characters, then click Next:

    • After installation, open the license manager and click Load License -> Copy License:

    • Locate the license file and click Open:

    • Click View License Status to inspect the license status:

    • Double-click the desktop shortcut to start Vivado.

    3. Standard Vivado Project Development Flow

    The complete flow for hardware verification with Vivado and an FPGA development board consists of the following six steps:

    Step 1: Create or Open a Vivado Project

    • Start Vivado. On the start screen, click Create Project; alternatively, select File -> Create Project in the upper-left corner.

    • Set the project name and path. Neither the project name nor its file path may contain Chinese characters or spaces.

    Create project subdirectory: This option is selected by default. It creates a subfolder with the project name under the specified path.

    • Select RTL Project as the project type.

    • The next screens add source and constraint files. Click Next to skip them for now; the files will be created separately later.

    • Under Default Part, search for and select the device used on the EGO1 development board: xc7a35tcsg324-1.

    Step 2: Add or Create Source Files

    • Three types of files must be added to the project: design sources, simulation sources, and constraints.
    • They can be added while creating the project (this method is not used here) or after the project has been created by clicking Add Sources (or the + icon).

    • Create a circuit design file (Design Source) named lab1_design.v. Enter lab1_design in File name.

    • Keep the default options, then click Finish -> OK.

    • The design file has now been created. The project view and the initial contents displayed after double-clicking the source file are shown below.

    • Complete the source file and save it.
    module lab1_design(
    input [7:0] sw,
    output [7:0] led
);
    assign led = sw;
endmodule
    • In the same way, create the simulation file (Simulation Source) lab1_sim.v. Complete the simulation code and save it.

    `timescale 1ns / 1ps

module lab1_sim( );

    reg [7:0] tb_sw = 8'h0000;
    wire [7:0] tb_led;

    lab1_design dut(
    .sw(tb_sw),
    .led(tb_led)
    );

    always #10 tb_sw=tb_sw + 1'b1;
endmodule
    • Create the constraint file (Constrain Source) lab1.xdc.

    • Enter the following pin constraints:
    set_property IOSTANDARD LVCMOS33 [get_ports {led[7]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[6]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[5]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[4]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[3]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[2]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[1]}]
set_property IOSTANDARD LVCMOS33 [get_ports {led[0]}]

set_property PACKAGE_PIN F6 [get_ports {led[7]}]
set_property PACKAGE_PIN G4 [get_ports {led[6]}]
set_property PACKAGE_PIN G3 [get_ports {led[5]}]
set_property PACKAGE_PIN J4 [get_ports {led[4]}]
set_property PACKAGE_PIN H4 [get_ports {led[3]}]
set_property PACKAGE_PIN J3 [get_ports {led[2]}]
set_property PACKAGE_PIN J2 [get_ports {led[1]}]
set_property PACKAGE_PIN K2 [get_ports {led[0]}]

set_property IOSTANDARD LVCMOS33 [get_ports {sw[7]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[6]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[5]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[4]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[3]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[2]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[1]}]
set_property IOSTANDARD LVCMOS33 [get_ports {sw[0]}]

set_property PACKAGE_PIN P5 [get_ports {sw[7]}]
set_property PACKAGE_PIN P4 [get_ports {sw[6]}]
set_property PACKAGE_PIN P3 [get_ports {sw[5]}]
set_property PACKAGE_PIN P2 [get_ports {sw[4]}]
set_property PACKAGE_PIN R2 [get_ports {sw[3]}]
set_property PACKAGE_PIN M4 [get_ports {sw[2]}]
set_property PACKAGE_PIN N4 [get_ports {sw[1]}]
set_property PACKAGE_PIN R1 [get_ports {sw[0]}]
    • Pin constraints consist of IOSTANDARD settings and PIN assignments. Set the IOSTANDARD of every port to LVCMOS33. The corresponding pins (PIN) can be found in Ego1_UserManual_v2.2.pdf or printed next to the associated peripherals on the development board.

    Step 3: Run Functional Simulation

    • In the Flow Navigator on the left, click Run Simulation.

    • Vivado generates a waveform that records the states of the circuit's input and output signals.

    • Important: Inspect the waveform carefully to verify the circuit's function. If the logic is incorrect, modify the design file and rerun the simulation. Proceed to on-board implementation only after the functional simulation passes. You may also experiment with the following controls and learn what each one does.

    Step 4: Synthesize, Implement, and Generate the Bitstream

    After confirming correct functionality, perform the following operations in order to convert the code into a hardware netlist:

    1. Click Run Synthesis.
    2. Click Run Implementation.
    3. Click Generate Bitstream to generate the final .bit file used to program the board.

    Important: If any Error or Critical Warning occurs during these steps, inspect and correct the project settings, design code, or constraint file before generating the bitstream again.

    Step 5: Connect the Development Board

    • Connect the computer to the USB-UART/JTAG port on the EGO1 development board using a data cable.

    • Turn on the EGO1 development board.

    • In Vivado, click Open Hardware Manager, followed by Open Target -> Auto Connect.
    • If the connection succeeds, the target device xc7a35t_0 appears in the Hardware window.

    Step 6: Program the Device and Verify It on the Board

    • In Hardware Manager, click Program Device, select the newly generated .bit file, and click Program.

    • When programming is complete, the "Done" LED on the EGO1 board lights up, indicating that the circuit has been successfully implemented on the FPGA.
    • Toggle the input switches and observe the outputs to verify that the hardware behaves as designed.

    4. Disconnecting the Hardware and Reconfiguring the Device

    4.1 Safe Disconnection

    At the end of the laboratory session, it is strongly recommended that you disconnect the development board in the following order. Never hot-plug the board while it is powered:

    1. Disconnect the software connection: Enter disconnect_hw_server in the Tcl Console at the bottom of Vivado and press Enter to disconnect Vivado from the FPGA.
    2. Disconnect the hardware: Turn off the EGO1 development board before unplugging the USB cable.

    4.2 Changing the FPGA Device in a Project

    If you selected the wrong device when creating the project, use the following steps to change it:

    • Under PROJECT MANAGER in the Flow Navigator, click Settings.

    • Select General, then click the ... button next to Project device to open the device selector.

    • Search for and select xc7a35tcsg324-1, then click OK.

    • Click Apply at the bottom of the Settings window to apply the configuration.

    • Close the Vivado project. In the project directory, delete the entire xxx.runs directory. This removes temporary files containing information about the previous device so that the change takes effect. Then restart Vivado.

    5. Laboratory Exercise

    1. Follow the development flow in this tutorial to implement and verify a simple switch-controlled LED circuit on the EGO1 development board.

    2. Input: Eight slide switches (sw[7:0])

    3. Output: Eight LEDs (led[7:0])
    4. Function: The position of each switch directly controls whether the corresponding LED is on or off.

    5. Check-off requirement: Reproduce the simulation waveform and demonstrate the circuit on the board.

    6. To support later exercises, you may download and install Vivado 2018.3 on your personal computer (optional).

    Vivado supports only Windows and Linux. Download the Linux installer from the AMD website.

    Running Vivado on macOS requires a virtual machine.
