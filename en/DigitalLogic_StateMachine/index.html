    Digital Logic: Finite State Machines

    Objectives

    • Understand the fundamental concepts of a finite state machine (FSM).
    • Understand the difference between Moore and Mealy state machines.
    • Master the three-process style for describing a state machine in Verilog.

    1. Finite State Machines

    1.1 What Is a Finite State Machine?

    A finite state machine (FSM) is a sequential-logic model that:

    • Has a finite number of states.
    • Moves from its current state to a next state under clock control, according to the current state and input signals.
    • Produces outputs according to the state and, in some machines, the inputs.

    State machines are fundamental tools in digital-system design and are widely used for control logic, protocol processing, sequence detection, and other applications.

    1.2 Components of a State Machine

    1.3 Moore Versus Mealy Machines

    Characteristic Moore machine Mealy machine
    Output depends on Current state only Current state and inputs
    Output changes After a state transition May change immediately when an input changes
    Number of states Usually greater Usually smaller
    Output stability More stable and synchronized to the clock May produce glitches
    Typical use Control logic and outputs that must be stable Logic that must respond quickly to inputs

    This course recommends Moore machines because their outputs are more stable and they are easier to understand and debug.

    2. Three-Process State-Machine Template

    The three-process style places the three parts of a state machine in three separate always blocks. This structure is clear, maintainable, and is the recommended standard style.

    2.1 Process 1: State Register (Sequential Logic)

    // 第一段：状态寄存器——在时钟边沿更新状态
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        state <= IDLE;       // 复位到初始状态
    else
        state <= next_state; // 更新为次态
end

    2.2 Process 2: Next-State Logic (Combinational Logic)

    // 第二段：次态逻辑——根据当前状态和输入，决定下一个状态
always @(*) begin
    case (state)
        IDLE: begin
            if (start)
                next_state = STATE_A;
            else
                next_state = IDLE;
        end
        STATE_A: begin
            if (condition)
                next_state = STATE_B;
            else
                next_state = STATE_A;
        end
        STATE_B: begin
            next_state = IDLE;
        end
        default: next_state = IDLE;
    endcase
end

    2.3 Process 3: Output Logic (Combinational Logic, Moore Type)

    // 第三段：输出逻辑——仅根据当前状态决定输出（Moore型）
always @(*) begin
    case (state)
        IDLE: begin
            led = 1'b0;
        end
        STATE_A: begin
            led = 1'b1;
        end
        STATE_B: begin
            buzzer = 1'b1;
        end
        default: begin
            led = 1'b0;
            buzzer = 1'b0;
        end
    endcase
end

    2.4 State Encoding

    Define state constants using localparam or parameter:

    // 状态定义
localparam IDLE    = 2'd0;
localparam STATE_A = 2'd1;
localparam STATE_B = 2'd2;

reg [1:0] state, next_state;

    Note: Both state and next_state are declared as type reg, but state is assigned in a sequential block and is synthesized as a register, whereas next_state is assigned in a combinational block and is synthesized as combinational logic.

    3. Two-Process State-Machine Template

    The two-process style differs from the three-process style as follows:

    1. Process 1: State register (sequential logic)
    2. Process 2: Combined next-state and output logic (combinational logic)

    3.1 Process 1: State Register (Sequential Logic)

    // 第一段：状态寄存器——在时钟边沿更新状态
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        state <= IDLE;       // 复位到初始状态
    else
        state <= next_state; // 更新为次态
end

    3.2 Process 2: Next-State and Output Logic (Combinational Logic)

    // 第二段：次态逻辑 + 输出逻辑（组合逻辑合并）
always @(*) begin
    // 根据当前状态和输入，决定次态和输出
    case (state)
        IDLE: begin
            if (start) begin
                next_state = STATE_A;
                led = 1'b1;          // 同时就输出
            end
        end
        STATE_A: begin
            led = 1'b1;              // Moore型输出
            if (condition)
                next_state = STATE_B;
        end
        STATE_B: begin
            buzzer = 1'b1;
            next_state = IDLE;
        end
        default: begin
            next_state = state;
            led = 1'b0;
            buzzer = 1'b0;
        end
    endcase
end

    Recommendation: Prefer the three-process style. It requires slightly more code but provides a clearer structure and is easier to maintain and debug.

    4. Laboratory Exercise: Count Detection

    4.1 Requirements

    Use both two-process and three-process styles to design a count-detection circuit with the following characteristics.

    Inputs:

    • clk: 100 MHz system clock
    • x_in[4:0]: Five-bit input sampled on each rising edge of clk

    Output:

    • y_out: Validity indicator

    Function:

    On each rising edge of the clock, the circuit samples the bits in x_in. It accumulates the total number of 1s received across all samples.

    • When the accumulated number of 1s is a multiple of 5, y_out = 1 (valid).
    • Otherwise, y_out = 0 (invalid).

    Example:

    Time x_in 1s in this sample Accumulated 1s y_out
    0 0b00001 1 1 0
    1 0b00001 1 2 0
    2 0b00001 1 3 0
    3 0b00011 2 5 1 ✓
    4 0b00111 3 8 0
    5 0b00010 1 9 0
    ... ... ... 15 1 ✓

    4.2 Moore or Mealy?

    • y_out depends only on the accumulated state, representing the total number of 1s received, and not on the current input.
    • The design is therefore a Moore state machine.

    4.3 Simulation and Verification

    Use a testbench to verify that the two-process and three-process implementations behave identically:

    `timescale 1ns/1ps
module tb_bit_counter();
    reg clk, rst_n;
    reg [4:0] x_in;
    wire y_out_2stage, y_out_3stage;

    bit_counter_2stage u1(...);  // 两段式
    bit_counter_3stage u2(...);  // 三段式

    initial clk = 0;
    always #5 clk = ~clk;

    initial begin
        rst_n = 0; #50; rst_n = 1;

        // 测试用例：单个1重复5次
        repeat(5) begin
            x_in = 5'b00001;  #100;
            x_in = 5'b00000;  #100;
        end

        // 此时应该回到state=0，y_out=1
        $finish;
    end
endmodule

    4.4 On-Board Verification

    Testing directly at the 100 MHz system-clock rate is difficult. Use a button, debouncing, and edge detection to emulate a sampling pulse.

    Procedure:

    1. Program the bitstream.
    2. Set five switches to configure x_in[4:0].
    3. Press the button once to sample x_in once.
    4. Observe the result:
    5. Optionally show the current state on the seven-segment display.
    6. Show y_out on an LED.
    7. y_out is asserted when the accumulated number of sampled 1s reaches a multiple of 5.

    5. Questions

    Q1: Can a Mealy machine be used?

    Approach:

    • Compute y_out = (next_state == S0) ? 1'b1 : 1'b0 in combinational logic.
    • The output will then respond immediately to an input change.
    • This approach can produce glitches and must be used carefully.

    Q2: Why is a single-process style discouraged?

    In a single-process design, state transitions and outputs are placed together in one always @(posedge clk) block.

    Disadvantages:

    1. Poor readability: Sequential and combinational logic are mixed and difficult to distinguish.
    2. Error-prone: It is easy to confuse blocking assignments (=) with non-blocking assignments (<=).
    3. Difficult maintenance: Logic changes can easily introduce bugs.
    4. Poor conformity: The style does not follow the recommended Verilog HDL design convention used in this course.
    5. Synthesis uncertainty: Different tools may interpret the description differently and produce different synthesis results.
